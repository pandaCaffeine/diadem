# Дерево в памяти — единственный источник правды для TUI и DLNA

До этого решения у Diadem было два независимых пути чтения диска: TUI работал по
результату полного `Scan`, а ContentDirectory на каждый `Browse` лениво перечитывал
папку через `library.ReadContainer` — с повторным снятием размеров и без общего
места для метаданных. С появлением Metadata понадобился один источник: `library.Store`
сканирует диск, держит последний снапшот дерева (атомарная замена указателя) и
кэш метаданных, а TUI и DLNA читают один и тот же снапшот. Ленивый дисковый путь
удалён.

Осознанная смена семантики: `Browse` теперь видит состояние на момент последнего
сканирования, а не «живой» диск. С fsnotify-ресканом с debounce 500 мс задержка
появления файла в клиенте неощутима, зато у `Browse` нет ни одного дискового stat,
а `childCount` — это `len(node.Children)`.

## Considered Options

- Общий кэш метаданных при двух путях чтения — меньше рефакторинга, но дублирование
  логики видимости и размеров остаётся
- Одно дерево в памяти для всех **(выбрано)**
- DLNA читает диск, TUI — дерево, метаданные только в TUI — два источника правды,
  расхождение гарантировано

## Consequences

- ObjectID — это путь узла в дереве; неизвестные и враждебные id (traversal, пустые
  сегменты) просто не совпадают ни с одним узлом — отдельная валидация путей не нужна
- Пока первый скан не дошёл до конца, `Browse` отвечает 701: окно в первые мгновения
  жизни сервера, клиенты повторяют запрос сами
- Снапшоты неизменяемы и меняются атомарно: читатели никогда не видят полу-дерево

# Метаданные видео читаем из заголовков сами; ffprobe — только эталон в тестах

Длительность (колонка в TUI) и `res@duration`/`res@bitrate`/`dc:title` в DIDL-Lite
требуют чтения заголовков контейнера. Внешний инструмент в рантайме (ffprobe) сломал бы
главное свойство Diadem — «один бинарник, одна папка, ноль зависимостей». Поэтому три
семейства контейнеров (MP4/MOV, Matroska, AVI) парсятся на чистом Go в `internal/format`:
по несколько килобайт заголовков на файл, с seek-ами вместо чтения тел. ffprobe
используется только в тестах как эталон (тест молча пропускается, если бинарника нет).

Идея не нова: BACKLOG откладывал её 2026-11-14 с формулировкой «VLC игнорирует
`res@duration`/`res@bitrate`». Возрождение изменило обоснование: главная ценность —
колонка длительности в собственном TUI при выборе фильма; DLNA-атрибуты — дешёвый
бонус поверх того же парсера.

## Considered Options

- Вызов ffprobe/ffprobe-обёртки в рантайме — просто и точно, но внешний процесс,
  установка ffmpeg как зависимость пользователя, парсинг чужого вывода
- Чистый Go: свои парсеры MP4/MKV/AVI **(выбрано)**
- Не извлекать метаданные вовсе — колонки не будет, а обходной путь «размер файла»
  длительность не заменяет

## Consequences

- Diadem остаётся одним бинарником без внешних процессов
- Свои парсеры — своя ответственность за корректность: эталон — ffprobe на реальных
  файлах из `testdata/`; синтетика в юнит-тестах покрывает краевые случаи (moov в конце,
  неизвестный размер Segment, OpenDML, отрицательный/чудовищный duration)
- Форматов меньше, чем раздаём: `.wmv`, `.ts` и прочие раздаются как раньше, но без
  длительности; расширение поддержки — новый файл в `internal/format`
- Юниты зафиксированы по спеке UPnP: `res@bitrate` — байты/сек (не биты), средний
  битрейт считается как размер/длительность
